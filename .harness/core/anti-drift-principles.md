# Anti-Drift Principles

## Drift Signals

- More than one canonical result schema exists.
- Adapter output bypasses canonical validation.
- Dashboard work starts before repeated artifact bundles.
- Required gates depend on LLM judges before calibration.
- Telemetry becomes the only proof path.
- Fixtures lack provenance, privacy class, or owner.
- Baseline comparison is missing from regression suites.
- Prompt text grows without measured eval improvement.
- Governance grows without schemas, validators, tests, or ADR protection.
- Linear issues multiply before the smoke command works.
- Future agents cannot identify runtime versus adapter versus repo-domain
  failure.

## Early Corrections

- Collapse duplicated schemas.
- Move framework fields to adapter metadata.
- Demote judge verdicts to advisory.
- Restore local artifact bundle as authority.
- Quarantine unsafe fixtures.
- Convert governance prose into a check or delete it.
- Reduce active Linear scope to executable-spine work.

## Operating Rule

Treat ambiguity as drift. If a future agent has to guess authority, owner,
proof, or route, add a small contract or remove the ambiguous path.

## Hard Block

Do not normalize drift because it is convenient. Temporary compatibility paths,
extra adapters, and duplicated orchestration need owners, sunset conditions, and
eval proof.
