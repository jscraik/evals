Decisions

2026-05-20 - Use one trust-boundary batch with per-gap owner modules

Decision: Implement JSC-333 through JSC-336 in dependency order as one coherent trust-boundary lane, but keep each gap mapped to a single owner module and exact seam test.

Why: The audit says false success is the highest-risk class. The deep-module contract requires each fix to hide coordination behind the owning module instead of distributing rules across callers and docs.

Rejected: Creating a broad orchestration layer or moving behavior into prompt instructions. That would violate phase-one scope and Jamie's mantra.

2026-05-20 - Keep simulation only as explicit synthetic execution

Decision: Preserve the existing synthetic smoke fixture, but make synthetic execution explicit in artifacts and keep real command execution as the default future boundary.

Why: The current smoke fixture is intentionally synthetic, but artifacts must not look like real execution evidence when no subprocess ran.

Rejected: Removing synthetic smoke immediately. That would expand scope and break phase-one bootstrap proof before replacement fixtures exist.

2026-05-20 - Add baseline-presence as a deterministic scorer

Decision: Add baseline-presence to the explicit scorer contract instead of hiding baseline mismatch handling in report prose or result status side effects.

Why: Baseline presence is a claim-vs-evidence check and should participate in deterministic verdicts with inspected inputs, evidence, and failure reason.

Rejected: Recording observed baseline state without letting it fail the run. That would preserve a false-success path for fixtures that claim a present baseline while the artifact is missing.

2026-05-20 - Use a small Node verify wrapper

Decision: Add scripts/verify.js and expose it as pnpm verify.

Why: The wrapper owns the AGENTS minimum validation lane and treats the credential-pattern check correctly: no matches is pass, matches is fail.

Rejected: A shell-only command chain in package.json. It would make result classification and regex exit-code semantics harder for agents to trust.

2026-05-20 - Address review feedback before PR delivery

Decision: Treat the post-phase review pass as part of the implementation, not an optional polish step.

Why: The requested workflow requires architecture, simplify, unslopify, Codex review, and testing checks after each phase. The reviewer pass found small but real contract-drift risks before commit.

Changes made from review: Removed duplicate simulated_command evidence, simplified baseline comparison branching, removed a runtime scorer allowlist that duplicated schema authority, and simplified the verify wrapper's command runner.

Rejected: Adding a larger latest-run schema migration in this patch. That belongs with the later trace/runtime artifact hardening phase, because this phase is scoped to false-success trust boundaries.
