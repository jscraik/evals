2026-05-23 - PU-001 requires artifact identity, not event counts

Decision: Change scoreSubagentArtifactContract from subagent-level event counting to artifact identity matching across subagent_id, artifact_type, and normalized artifact_path.

Why: Count-based evidence can pass when a subagent writes the wrong artifact. The trust boundary needs to prove the exact expected artifact identity.

Contract note: The scorer revision is subagent-artifact-contract version 1.1.0. Covered drift scenarios now include wrong path, wrong type, wrong subagent, missing identity, traversal path, and ambiguous duplicate writes.

Rejected: Reading artifact files from disk inside the scorer. PU-001 verifies event identity only; artifact existence belongs to artifact bundle validation.

2026-05-23 - PU-001 review findings resolved before progression

Decision: Fix the architecture high finding, the cross-subagent keying issue, the derived-count simplification, the missing type/subagent tests, and the docs addendum before marking PU-001 complete.

Why: The mandatory review stack found concrete validation and governance gaps. Progressing with unresolved findings would violate the slice lifecycle.

Deferred: Low-value test helper extraction and generic push-helper simplification. These are local readability suggestions with no current runtime safety effect.

2026-05-23 - PU-002 makes policy coverage fail closed

Decision: Add runtime-evidence policy coverage under runtime_evidence.policy_coverage in pnpm evals check --json. Declared enforced families must have their scorer present; scaffolded families must declare scaffolded_not_enforced with a reason.

Why: Without machine-readable coverage, the suite can appear green while declared runtime policy families have no enforcing scorer.

Contract note: Permission, subagent artifact, and plugin attribution policies are enforced by scorers. Goal, thread, network, and package provenance remain explicit scaffolds in phase one and are not runtime authority.

Rejected: Treating unscored declared policy as informational. The revised contract fails closed with RTE_POLICY_*_UNSCORED errors.

2026-05-23 - PU-003 makes runtime state consume runtime-evidence health

Decision: Bump the runtime-state packet to schema_version: 2 and add contract_health.runtime_evidence plus non_ready_reason_code.

Why: pnpm evals state --json previously only reflected latest-run health. It could report ready while pnpm evals check --json would fail runtime-evidence contracts.

Contract note: Runtime-evidence failure now makes top-level state invalid, sets non_ready_reason_code to runtime_evidence_failed, and recommends pnpm evals check --json.

Rejected: Adding an advisory warning without changing readiness. That would preserve the false-ready path.
