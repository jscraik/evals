How the Deep Modules Work

This is the JSC-370 implementation map. The point is to put each trust boundary behind one owner module, then make callers use that owner instead of copying rules across commands, tests, docs, or agent prompts.

Owner Module: Run Bundle Allocation

  • src/lib/run-bundle.js owns run ID and artifact directory allocation.
  • It creates the directory atomically, then retries with a numeric suffix only on collision.
  • Callers receive runId, runDir, and artifactRoot; they do not construct competing paths.
  • Seam proof: two identical runs in the same second must not share a directory.

Owner Module: Latest Proof Context

  • src/lib/latest-run.js compares expected smoke context with observed latest context.
  • It returns match, mismatch reason, and recovery command.
  • The recovery command is supplied by the caller that owns the expected smoke path.

Validation Owner

  • src/lib/latest-run.js stays responsible for artifact-bundle validation and proof-context validation.
  • When expected context is supplied, context mismatch fails before artifact paths are trusted.

Caller Contract

  • src/commands/run.js writes a run-local latest candidate first.
  • It publishes .harness/evals/runs/latest.json only after result, manifest, trace, scorer, baseline, command log, and report validate together.
  • src/commands/validation.js derives expected context from the canonical smoke case, not from prose or prior run memory.

Public Interface

  • check --json adds expected_context, observed_latest_context, context_match, mismatch reason, and recovery command.
  • The JSON change is additive to preserve existing consumers.

Rollback and Tracer Proof

Rollback is a revert of the owner modules and callers. Trace remains explanatory evidence inside the final bundle; artifacts still decide.
