## Decision Log

- Created the goal as a parent implementation loop instead of a single patch
  task because the audit spans several trust boundaries and needs slice-level
  validation.
- Ordered P0 work around false-success and stale-evidence risk before broader
  architecture maturity, matching the audit's highest-leverage fix sequence.
- Used `docs/goals/2026-05-26-evals-evidence-led-gap-audit/` for the board so
  the Goal Governor validator can locate implementation notes using its
  documented board-layout conventions.
- Kept setup separate from feature implementation to avoid mixing goal
  scaffolding with runtime changes in an already dirty worktree.
- Started T002 with scripts/verify.js as the owner module for aggregate gate
  ordering and src/lib/latest-run.js as the hidden latest-validation authority.
- Added a pre-mutation latest integrity check before smoke commands so corrupt
  preexisting latest evidence fails before pnpm verify can refresh smoke
  artifacts.
- Classified absent latest state as a setup pass because clean repositories may
  rely on the smoke run to create the first latest pointer before post-smoke
  validation.
- Advanced the goal board to T003 only after local validation passed and the two
  required T002 reviewer artifacts existed and were non-empty.
- Implemented T003 as an additive CLI contract: pnpm evals check --json now
  validates the observed latest packet, while pnpm evals check --smoke --json
  performs the stricter smoke proof-context binding used by pnpm verify.
- Kept observed latest context in validateLatestRun() even when no expected
  context is supplied so machine consumers can see what was validated without
  inheriting smoke-only assumptions.
- Updated README and AGENTS validation wording after confirming the live
  package scripts and CLI help expose the new command surface.
- Added a verify wiring regression after adversarial mailbox review called out
  that the aggregate gate must remain bound to pnpm evals check --smoke --json
  rather than the permissive observed-latest default.
- Marked T003 complete with an explicit adversarial coverage gap: the reviewer
  returned no blocking mailbox findings twice but did not write the required
  artifact after one focused retry.
- Implemented T004 as a schema-owned public envelope for validation and check
  command JSON results, with detailed nested evidence remaining owned by the
  command-specific result builders.
- Allowed `strict_smoke_command` to be `null` in the schema because live
  `check --smoke --json` output currently emits null for that metadata field;
  the slice records the observed behavior instead of inventing a stricter
  runtime guarantee.
