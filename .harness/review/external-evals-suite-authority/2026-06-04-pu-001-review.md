Slice: PU-001 external project manifest contract

## Summary

Status: pass after one review fix.

The slice adds a closed external project manifest schema, one semantic owner module, fixtures, and focused tests. It does not add target project execution, adapters, plugin systems, judge gates, or external runner behavior.

## Simplify Review

Decision: pass.

The implementation keeps the contract small and data-only. The schema owns closed shape and enum vocabulary. src/lib/external-project-manifest.js owns the semantic checks that the local schema subset cannot express: repository-relative path boundaries and first-slice black-box blocking.

No extra abstraction was added beyond the owner module required to avoid scattering policy checks through callers or tests.

## Improve Codebase Architecture Review

Decision: pass after fix.

Owner module: src/lib/external-project-manifest.js

Public interface:

- externalProjectManifestPath
- validateExternalProjectManifest
- classifyMissingExternalProjectManifest

The implementation follows the repo architecture contract: command wiring is untouched, reusable behavior lives in src/lib, schema registration stays in src/lib/schema.js, and fixtures/tests prove the contract. The missing-manifest classifier returns structured actions rather than opening a behavioral command path.

Finding fixed: initial path validation only split traversal on POSIX separators and relied on platform-local path.isAbsolute, which would miss Windows-style absolute paths on macOS. The owner now uses both POSIX-local absolute detection and win32.isAbsolute, and splits traversal on both slash styles. Focused tests cover both cases.

## Residual Risk

The schema vocabulary names black_box_execution even though PU-001 blocks it. This is intentional so future slices can classify requests without inventing new terms. The guard is that first-slice validation rejects black-box as default mode and missing-manifest classification returns blocked or human-approval-required actions with command: null.
