Decisions Not Fully Specified

DecisionChoiceWhy
Runner language Plain Node ESM rather than TypeScript build tooling. The reuse map recommended TypeScript/Node, but the plan also demands a tiny offline phase-one command. Plain Node keeps the command local and avoids introducing build dependencies before the spine proves itself.
Schema validation Hand-written runtime validation plus JSON Schema files. Adding Ajv or a similar dependency would be reasonable later, but phase one can validate required fields directly and keep the dependency surface empty.
Smoke execution Simulated synthetic case output. The fixture is synthetic by requirement. Running arbitrary repo commands belongs in a later consuming-repo suite contract.
Privacy metadata name contains_credentials instead of contains_secrets. The plan's lightweight regex checks secret in fixtures and eval artifacts. A false-valued field containing that word self-triggered the gate, so I used equivalent credential wording in generated artifacts.
Ubiquitous language surface Added UBIQUITOUS_LANGUAGE.md and wired it into README/AGENTS read order. The named ubiquitous-language review expects a glossary and instruction pointer, so this turns the fallback review into a concrete repo surface.
Review fallback Coordinator-run review artifacts after subagent artifact failures. The requested review agents either stalled or failed to write artifacts. A later one-agent probe reproduced the missing-artifact failure. I preserved that in artifacts/reviews/review-coordination.md and wrote fallback lens artifacts for simplify, ubiquitous-language, architecture, unslopify, testing-reviewer, and CodeRabbit rather than claiming agent approval.
